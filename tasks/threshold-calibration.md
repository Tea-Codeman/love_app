## 供未来校准的两个观察（不做现值修改）

1. **游戏成长权重可能偏高**：2–3 局游戏 + 少量聊天即可到 150 封顶（当日完成 S0→S4 全程）；且「0 聊天」的 pair 也能纯靠游戏到 S4——growthValue 与「关系质量」区分度弱。未来校准时优先复算游戏/聊天/连续互动的权重配比，而非只调切点。
2. **`app_open` 冷启动双计（数据质量）**：onLaunch 与 onShow 在冷启动时先后各报一次（时间戳成对、相差毫秒级），DAU/SC2 分母约虚高一倍。建议后续修复（如 onLaunch 打标记跳过紧随的 onShow），修复前解读 SC2 时需除以 ~2。

## 校准方法备忘（下次数据足够时照此执行）

1. 取 `pairs` 全量，按 growthValue 分桶（初值切点 12/40/90/150）。
2. 每桶统计：互聊 ≥3 轮比例、contact_unlocked 比例、D7 仍互动比例（`app_open` 按 pair 聚合跨天）。
3. 找代理指标跃迁明显的 growthValue 切点；与初值对比后决定是否改 `growth-core.js` 阈值常量（改后需 `npm run sync:core` + 重部署 growth/game/chat/match）。
