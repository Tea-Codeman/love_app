## 2. V1 双设备撮合→破冰闭环（核心）

> 关键机制：A 点「一起玩」→ 云端建 `matches(active)` + `games(waiting)` → A 进游戏房等；B 的匹配页每 2.5s 轮询到邀请 → 点「接受」→ 自动 `joinGame` 载入 5 题 → `playing`；双方各答 5 题，每轮双方都提交后自动进下一题；第 5 题双方提交 → `done`。

**机 A（发起人）**
1. 主页 → 匹配破冰。等 1~2 秒，「为你推荐」出现候选卡（含机 B 的昵称）。
2. 在候选卡里找到**机 B 的昵称** → 点「一起玩」。
3. 跳转游戏房，显示「⏳ 已发起，等待对方加入…」。保持此页不动。

**机 B（受邀人）**
4. 主页 → 匹配破冰。顶部「有人想和你玩 ›」出现机 A 的邀请卡（若没立刻出现，等 ≤3 秒轮询）。
5. 点「接受」。
6. 跳转游戏房，自动加入，进入第 1/5 题。

**两人同步答题（每题都点，别等对方）**
7. 双方各自在本题选一个选项 → 页面显示「已选择，等待对方…」。
8. 当两人都选完，自动跳下一题（显示「双方已选，马上进入下一题」）。
9. 重复到第 5/5 题双方都提交。

**结束**
10. 两台手机都显示 💞「默契 X/5 题」+ 文案 + 「完成破冰」按钮。点它回大厅。

**判定**：两台都到结束页即 V1 通过。我随后在云端查该 `games` 是否 `done`、`matches` 是否 `done` 且 `lastTacit` 与页面数字一致。

> 注：游戏房同步默认走云数据库 watch，若环境安全规则拒绝客户端直读 `games`，会自动降级为每 1.5s 轮询 `getGame`（云函数），**双端仍能一致推进**。若你发现某一方卡在「等待对方」不动，多半是网络/watch 降级延迟，等 ≤3 秒即可。

## 3. V2 MBTI 测评保存

**机 A 与机 B 各做一次**
1. 主页 → 我的资料。
2. 点「MBTI · 未测评」行 → 进入 12 题测评。
3. 逐题选，实时预览会随进度显示临时类型（已修：未答题时不再误显 ESTJ）。

**判定**：我查 `users` 该 openid 是否出现 `mbti` 字段。保存后回匹配页，对方候选卡应出现「MBTI xx」标签（契合度打分已含 MBTI 维度加分）。

## 4. V3 拉黑 + 解除

**机 A 操作（对机 B 或某个旧候选均可；建议对机 B 验证"推荐过滤"最直观）**
1. 匹配页候选卡 → 点「拉黑」→ 弹窗确认「拉黑」→ Toast「已拉黑」。该卡本地立即消失。
2. 我查 `blocks`：应新增 `{blockerId=A, blockedId=目标}`。
3. 机 A 下拉刷新/重进匹配页 → 该目标**不再出现**在推荐（服务端过滤生效）。
4. 主页 → 设置 › → 黑名单：看到该用户条目。
5. 点「解除」→ 确认 → Toast「已解除」。
6. 我查 `blocks`：该条被移除（`removed=1`）。
7. 机 A 重进匹配页 → 该用户**重新出现**。

**判定**：拉黑后消失、解除后重现，且云端 `blocks` 增删一致 → V3 通过。
